# Leave Management System (LMS)

A full-stack web application for managing employee leave requests. Employees can submit and cancel leave across multiple leave types, and managers can approve or reject requests - all through a clean, role-aware interface.

> **This implementation was entirely generated by [PostQode](https://postqode.ai).**

---

## Overview

LMS is built with a **React** frontend and an **ASP.NET Core** minimal API backend. It demonstrates role separation, per-type leave balance tracking, date validation, and a multi-state request lifecycle.

**Key capabilities:**
- Five pre-seeded employees, selectable from the Employee view
- Four leave types - Annual, Sick, Casual, and Unpaid - each with independent balances
- Submit leave requests with start and end dates (weekdays only; past dates rejected)
- Track per-type leave balance in real time
- Cancel own pending requests
- Manager approval with per-type balance validation
- Manager rejection with a mandatory reason
- Role-filtered navigation - each role sees only relevant nav items

## Getting Started

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download)
- [Node.js 20+](https://nodejs.org/)

### 1. Start the backend

```bash
cd backend
dotnet run
```

The API will be available at `http://localhost:5000`.

### 2. Start the frontend

```bash
cd frontend
npm install
npm run dev
```

The app will be available at `http://localhost:5173`. The Vite dev server proxies all `/api` requests to the backend automatically.

## Leave Types and Balances

Each employee starts with the following baseline entitlement per leave year:

| Leave Type | Baseline Days |
|------------|---------------|
| Annual     | 15            |
| Sick       | 10            |
| Casual     |  5            |
| Unpaid     | Unlimited     |

Balances are independent per type. Days do not transfer across types. Only **Approved** requests consume balance - Pending, Cancelled, and Rejected requests do not.

---

## Business Rules

### Submission
- `leaveType` is required. Missing or unrecognised values return 400.
- Start date must be today or in the future. Past start dates return 400.
- The day count is calculated in **weekdays only** (Monday–Friday). Weekends are excluded.
- A date range with zero weekdays (e.g. Saturday–Sunday) returns 400.
- Submission is permitted regardless of remaining balance. Balance is checked at approval time.
- Unpaid leave is always submittable with no balance constraint.

### Approval
- Only Pending requests can be approved.
- For Annual, Sick, and Casual: approval fails if the employee's remaining balance for that type is less than the requested days.
- Unpaid leave is always approvable — no balance check is performed.

### Rejection
- Only Pending requests can be rejected.
- A rejection reason is required. Empty or whitespace-only reasons return 400.
- Rejection does not affect balance.
- The rejection reason is stored on the request and visible to both the employee and the manager.

### Cancellation
- Only Pending requests can be cancelled.
- An employee can cancel only their own requests. Attempting to cancel another employee's request returns 403.
- Cancellation does not affect balance.

### Request lifecycle
```
Pending -> Approved
Pending -> Cancelled
Pending -> Rejected
```
All three are terminal states. No further transitions are permitted.

## API Reference

### Health and shell

| Method | Endpoint      | Description                    |
|--------|---------------|--------------------------------|
| GET    | `/api/health` | Health check                   |
| GET    | `/api/shell`  | Navigation and role config     |

### Employees

| Method | Endpoint        | Description              |
|--------|-----------------|--------------------------|
| GET    | `/api/employees`| List all employees       |

### Employee endpoints

| Method | Endpoint                                       | Description                |
|--------|------------------------------------------------|----------------------------|
| GET    | `/api/employee/balance?employeeId={id}`        | Per-type balance breakdown |
| GET    | `/api/employee/leave-requests?employeeId={id}` | List own requests          |
| POST   | `/api/employee/leave-requests`                 | Submit a new request       |
| POST   | `/api/employee/leave-requests/{id}/cancel`     | Cancel a pending request   |

**Submit request body:**
```json
{
  "startDate": "2026-08-04",
  "endDate": "2026-08-08",
  "leaveType": "Annual",
  "employeeId": 1
}
```

Valid `leaveType` values: `Annual`, `Sick`, `Casual`, `Unpaid`.

All employee-scoped endpoints return 404 if `employeeId` does not correspond to a known employee.

### Manager endpoints

| Method | Endpoint                                   | Description                  |
|--------|--------------------------------------------|------------------------------|
| GET    | `/api/manager/leave-requests`              | List all team requests       |
| POST   | `/api/manager/leave-requests/{id}/approve` | Approve a pending request    |
| POST   | `/api/manager/leave-requests/{id}/reject`  | Reject a pending request     |

**Reject request body:**
```json
{
  "reason": "Team is short-staffed that week."
}
```

### Response: leave request record

All endpoints that return leave request records include these fields:

| Field          | Type    | Notes                                             |
|----------------|---------|---------------------------------------------------|
| `id`           | int     |                                                   |
| `employeeId`   | int     |                                                   |
| `employeeName` | string  |                                                   |
| `leaveType`    | string  | `Annual`, `Sick`, `Casual`, or `Unpaid`           |
| `startDate`    | string  | ISO 8601 date                                     |
| `endDate`      | string  | ISO 8601 date                                     |
| `days`         | int     | Weekday count only                                |
| `status`       | string  | `Pending`, `Approved`, `Cancelled`, or `Rejected` |
| `reason`       | string? | Populated only on Rejected requests               |

### Response: balance breakdown

`GET /api/employee/balance` returns an array — one entry per leave type:

| Field          | Type    | Notes                       |
|----------------|---------|-----------------------------|
| `leaveType`    | string  |                             |
| `isUnlimited`  | bool    | `true` for Unpaid           |
| `baselineDays` | int     | `0` for Unpaid              |
| `usedDays`     | int     | Days from Approved requests |
| `remainingDays`| int?    | `null` for Unpaid           |

## UI

### Navigation

Navigation items are filtered by role:

| Role     | Nav items                          |
|----------|------------------------------------|
| Employee | Dashboard, My Leave Requests       |
| Manager  | Dashboard, Team Leave Requests     |

### Role switcher

Use the Role dropdown in the sidebar to switch between Employee and Manager views. Views are never shown side by side.

### Employee selector

When in Employee role, a second dropdown in the sidebar allows switching between the five pre-seeded employees. Switching employee reloads the balance and request list for that employee.

## Known Limitations

- State is held **in memory** on the backend and resets on server restart. There is no database.
- There is no authentication. Employee identity is determined by the selector value in the UI, or the `employeeId` parameter in API calls.
